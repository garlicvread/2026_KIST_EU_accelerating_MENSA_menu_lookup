# 메뉴 가짓수 변경 허용

## 승인된 요구사항

식당 원본에 있는 메뉴의 개수·증감량·증감률은 수집 실패를 판단하는 근거로 사용하지 않습니다. 이 변경은 이슈 #5와 중복 항목 감소를 가격 누락으로 오인하는 이슈 #6을 해결합니다.

## 변경할 동작

`mensa.menu_contract.validate_menu`는 새 식단과 이전 식단의 형식 및 가격 출처를 각각 검증합니다. `_validate_previous`는 날짜 연결과 계속 존재하는 메뉴의 가격 소실만 검사하고 메뉴 개수나 과거 중복 발생 수를 비교하지 않습니다. 동일 메뉴의 현재 발생 중 하나 이상에 유효한 가격이 있으면 중복 개수 감소를 가격 소실로 판단하지 않습니다. 계속 존재하는 동일 메뉴의 현재 발생에 가격이 전혀 없으면 기존 가격 소실 검증을 유지합니다.

`scripts.menu_source.parse_menu`는 유효한 날짜 탭·패널 안에 판매대나 메뉴가 없더라도 해당 날짜를 빈 식단으로 반환합니다. 판매대가 있다면 이름·위치와 원문 요소 연결을 검증합니다. 두 HTML 파서의 원문 요소 집계와 추출 결과가 일치해야 하며, 잘못된 날짜 연결·잘린 원문·고아 메타데이터·잘못된 가격표를 빈 식단으로 숨기지 않습니다.

기존 JSON 형식과 브라우저는 빈 `meals` 목록을 지원하므로 형식을 변경하지 않습니다. 번역 생성·모델 설정·공개 큐의 계약도 변경하지 않습니다.

## 검증과 전달

감소·증가·교체·중복 감소·혼합 가격 상태·빈 판매대·판매대 없는 휴무일의 회귀 테스트를 먼저 작성합니다. 실제 가격 소실과 기존 파싱 오류는 계속 거부해야 합니다. 수집부터 파일 교체까지의 테스트로 새 메뉴 가짓수가 게시 데이터에 반영되는지 확인합니다.

검증된 변경은 `garlicvread`·`ceo@aidall.tech`로 SSH 서명하여 전달하고 GitHub의 실제 검증 결과를 확인합니다. 반영 후 기존 수집 작업으로 새 식단을 게시하여 수집 시각 갱신을 확인합니다.
