# 정상 원본 변경과 번역 작업의 분리

사용자는 앞서 확인한 검사 조건을 재평가하고 실제 결함을 모두 수정하도록 요청했습니다. 가격의 출처·날짜·대상과 잘못된 번역을 검증하는 기능은 유지하며, 정상적인 가격 표기 차이와 항목별 미확인 상태 때문에 새 메뉴 전체를 게시하지 못하는 동작을 수정합니다. 기존 무료 Drive·Pages 구조, 보관 한도, 원문 경고와 교정 번역을 유지합니다.

## 재평가 결과

가격표의 굵은 글씨 태그, 유로 기호, S/M/G 순서 때문에 같은 금액을 거부하는 동작은 형식 결합 결함입니다. 라벨별 금액을 해석하고 원문 raw를 보존합니다. 닫힌 가격 문단·요리 소유 관계·구성품 설명 제외·미소비 가격 표식 검사는 유지합니다. S/M/G 각각 하나와 양의 정수 센트가 확정되지 않는 가격은 추정하지 않습니다.

과거 가격이 있었다는 이유로 현재 원본의 미기재를 차단하는 규칙은 의도된 손실 방지 정책이었습니다. 현재 문서의 구조·가격 표식 검사를 통과한 실제 미기재에는 기존 null/source_pending 상태를 사용하도록 정책을 변경합니다. 과거 금액을 복사하지 않으며 이전 날짜 누락과 잘못된 출처 연결 검사는 유지합니다.

번역이 완성돼야 게시한다는 규칙도 의도된 정책이었습니다. 그러나 모델 실패·대기·자원 부족으로 확인된 새 가격까지 오래된 상태로 남기는 가용성 결함을 만듭니다. 화면은 이미 항목별 독일어 대체 표시를 지원하므로, 게시 가능성과 번역 완료를 별도로 판단합니다.

## 가격 해석

수집기는 구성품 밖의 닫힌 가격 문단에서 정규화한 표시 텍스트가 Preise와 콜론으로 시작하는지 확인합니다. strong/b/span 등의 글씨 꾸밈에는 의존하지 않습니다. 가격은 |로 나눈 세 항목이며 각 항목에는 S/M/G 중 하나의 라벨, 콜론, 두 자리 소수 금액, 선택적인 끝의 €만 허용합니다. 라벨 순서와 소수점/소수 쉼표는 달라도 됩니다. 라벨 중복·누락·알 수 없는 라벨·추가 문구·음수·0·범위 초과는 거부합니다. Python과 TypeScript가 같은 규칙을 사용하고 raw와 provenance를 유지합니다.

## 게시 계약

validate_publication은 존재하는 번역의 스키마·두 언어·원문 키·구성품 수·바이트 토큰을 검사합니다. 특정 요리명·안내 번역·기존 LLM 문장과의 정확한 동일성은 유효성 조건이 아닙니다. 없는 번역이나 주의 표시 번역은 게시 결함으로 취급하지 않습니다. 공개 메뉴의 독일어 이름·구성품·주의 표시는 항상 보존합니다. recover_cache는 기존의 손상된 개별 번역을 제외하고 정상 항목을 보존하며 해당 항목을 현재 원문으로 재생성할 수 있게 합니다. public_translations는 사용 가능한 참조 번역만 투영하며 미완성 번역을 꾸며 넣지 않습니다. translation_gaps는 없거나 사용할 수 없는 요리 번역 키와 주의 표시 라벨을 반환하여 번역 작업의 완료 판단에 사용합니다. Drive envelope와 릴리스 해시·사이트 JSON 스키마는 바꾸지 않습니다.

이전 문장과 정확히 같아야 게시한다는 테스트는 잘못된 전제를 고정하므로 제거·교체합니다. 서로 다른 유효한 표현의 허용, 개별 손상의 제외·재생성, 정상 형제 항목과 새 가격의 게시를 검사합니다. 원본 가격·날짜·원문 연결·원래 게시 바이트 해시의 동일성과 명시적으로 주입한 편집 입력의 전달 검사는 유지합니다. 사전은 작성 입력이며 번역 의미의 정확성을 증명하지 않습니다.

## 수집 작업과 번역 작업

Drive와 directory 모드의 수집 작업은 새 원본 검사, 보관 범위 적용, 공개/비공개 캐시 병합, 검토 사전·편집 문구의 결정적인 적용, 공개를 수행합니다. 이 단계는 모델을 시작하지 않습니다. 기존 source queue.json과 Drive 게시 저널은 수집·업로드 복구를 계속 담당합니다.

번역은 같은 worker.lock 아래 별도 translation-work.json으로 관리합니다. 최신 공개 묶음을 작업 입력으로 사용하므로 독일어 메뉴 전체를 또 저장하지 않습니다. 상태에는 대상·준비 릴리스 ID, 이전 릴리스 ID, 시도 횟수, 다음 시도 시각, 안전한 오류 코드와 영구 오류 여부만 유한하게 보관합니다. source queue의 기간·Git 필드를 번역 릴리스로 재사용하지 않습니다.

JobRunner는 유효한 작업 상태에서 수집을 먼저 처리하고 선택적인 번역 작업을 호출합니다. Drive/directory의 모델 자원 검사는 번역 단계에 적용하며 legacy Git 실행의 기존 의미는 유지합니다. 번역 대기·실패·영구 오류는 별도 결과로 표시하고 성공한 수집을 실패로 되돌리지 않습니다. 유지보수·설정·상태 파일 검사 자체가 실패한 경로에서는 모델을 시작하지 않습니다. 상태 조회는 파일만 읽으며 Drive·모델에 연결하지 않습니다. 명시적인 retry-translations는 같은 잠금 아래 번역 대기만 해제하고 시도 이력을 보존합니다.

Drive의 --base와 --config는 동일한 설정 기반 실행기를 사용합니다. 이전 Mac 설치의 모델·경로·메모리 값이 정확히 같을 때 별도 번역·캐시 경로를 고르던 호환 분기는 제거합니다. 기존 설정·가중치·캐시는 보존하고 호환되지 않는 생성 이력만 별도 번역 단계에서 갱신합니다. 운영체제 차이는 자동 실행 등록·자원 측정·경로 설정에 한정합니다. 이 결정은 이전 Drive 전환 설계의 네이티브 번역 재사용 방침을 대체합니다.

번역은 기존 모델·검증·항목별 체크포인트를 재사용하며, 성공한 항목을 비공개 캐시에 저장한 뒤 같은 메뉴와 개선된 번역을 게시합니다. 인증·설정 오류의 수동 재시도 정책은 유지합니다. 잘못된 개별 생성 응답은 미완성으로 남기고 다음 항목을 처리하며, 남은 번역은 대기 후 재시도합니다. 이 정책은 다음 수집과 가격 갱신을 차단하지 않습니다.

## 복구와 보관

수집 업로드의 결과가 불명확하면 번역 전용 게시를 보류하여 준비본의 기준을 바꾸지 않습니다. 번역 게시에도 이전 공개 ID와 준비 ID를 기록합니다. 공개 묶음이나 교정이 바뀌면 오래된 번역 게시 준비만 버리고 최신 공개본과 유효한 비공개 번역에서 다시 준비합니다. 새 메뉴 위에 과거 메뉴를 덮어쓰지 않습니다. 동시 원격 작성의 트랜잭션 보장은 추가하지 않습니다.

번역 재시도만으로 last_used를 늘리지 않습니다. 새 원본의 실제 관찰만 사용일을 갱신합니다. 기존 메뉴·캐시·복구본·용량 한도를 유지하고 번역 상태 파일은 비공개 일반 파일·원자적 교체·크기 제한을 적용합니다. 새 상태 파일 때문에 무제한 과거 릴리스를 보호하지 않습니다.

## 검증

같은 금액의 HTML/€표기/라벨 순서 변형, 실제 가격 미기재 전환, 미번역 요리·주의 표시의 원문 대체, 잘못된 가격 연결·중복 라벨·손상된 번역 거부를 회귀 검사합니다. 모델 자원 부족·미래 재시도·영구 실패 중에도 다음 수집이 완료되는지 검사합니다. 수집 없는 번역 재개, 공개 교정 보존, 업로드 응답 손실과 새 수집 경합, 상태 조회·명시적 재시도·잠금·보관 한도도 검사합니다. 전체 CI와 코드 리뷰를 마친 뒤 기존 Mac과 Pages에 적용합니다.
